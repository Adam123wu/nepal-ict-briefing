## Development

`npm install --legacy-peer-deps` then `npm run build`. GitHub Pages uses the `/nepal-ict-briefing` base path; local development does not.

Edit `config/` inputs, never generated `data/`. Read `skills/nepal-ict-briefing/SKILL.md` and `NEPAL-WORKFLOW.md` before an editorial refresh. The daily GitHub workflow collects candidate links at 01:30 Nepal time; it does **not** manufacture or automatically approve news. Daily editorial review is a separate Codex task at 02:00 Asia/Baghdad (04:45 Nepal), requiring the computer and app to remain running with project/network access.

The 18 September attachments are integrated into twelve monitoring focus groups and seventeen domain mappings, adding fourteen web endpoints to the prior registry. Download the original planning workbook from `public/resources/Nepal_Media_Monitoring_with_News_Sources.xlsx`. The original attachment skill is preserved as reference in `skills/nepal-ict-briefing/references/attachment-skill.md`; the executable project workflow is the parent SKILL.md. No email body, signature, login data or private account details are uploaded. Raw-language keywords stay in research configuration, not public news narratives.

Run `python3 scripts/test_nepal_monitoring.py` to test keyword boundaries, Nepali normalization, safe disaster triage and tracking-URL deduplication.

## Evidence and credentials

News dates describe events or dated announcements. Social review dates are explicitly labelled and are not inferred posting timestamps. Official notices are separate from business commentary. No aggregate compliance score is assigned until all dimensions have adequate evidence.

This public repository contains no credentials or Telegram session. No Nepal Telegram channel is currently ownership-verified or enabled; public web/social observations do not imply an authenticated Telegram scan. Secrets in another repository are not inherited here. Never commit `.env`, `.secrets`, phone numbers, login codes or session files.
